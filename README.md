# kokky

Музыкальный плеер в тёмном минималистичном стиле — HTML, CSS и ванильный JS.
Интерфейс повторяет референс, но под брендом **kokky**.

## Что внутри

- **Живая лента** без вшитых подборок: при запуске собираются популярные
  треки по нескольким жанровым запросам, а поиск идёт по всему каталогу.
- При первом заходе **«Мой поток»** предлагает начать с поиска: после первых
  запросов, прослушанных треков и лайков лента собирается уже из твоих артистов
  и жанров. Вкус хранится локально в `kokky:taste:sc`, а поток обновляется сам.
- Раздел **«Исполнители»**: курируемый список популярных артистов СНГ (`artists`
  в `library.js`). В карточке артиста — все его треки, которые реально есть в
  каталоге: кнопки **«Играть»** и **«Перемешать»**, нумерация и переход к плееру
  по клику. Список треков кэшируется на 6 часов в `localStorage`
  (`kokky:artist:sc:*`), поэтому повторное открытие мгновенное.
- Раздел **«Плейлисты»**: квадратная кнопка **«создать плейлист»**, свои плейлисты
  сохраняются в `localStorage`.
- После создания плейлист открывается: внутри можно добавлять треки через поиск,
  убирать их и запускать весь список.
- На «Моём потоке» кнопка **«Добавить в плейлист»** рядом с перемоткой — выбираете,
  в какой из своих плейлистов положить текущий трек. То же действие есть в меню `⋯`.
- Источник — **открытый музыкальный каталог**: полные треки, без аккаунта, подписки
  и API-ключей. Отрывки длиной 30 секунд (`policy: SNIP`) отфильтровываются.
- Звук играет **нативный `<audio>`**: приложение получает прямой поток трека
  (progressive MP3, а если его нет — HLS через локальный `hls.js`). Поэтому
  воспроизведение не зависит от заблокированного домена встроенного плеера и
  работает без VPN. Встроенный плеер остаётся резервным вариантом и грузится
  только если прямой поток получить не удалось.
- Поиск работает в два слоя: мгновенно по загруженной ленте и через живой поиск
  по всему каталогу (с задержкой 260 мс и защитой от гонок).
- Полноценное управление: перемотка, пауза, следующий/предыдущий трек, автопереход,
  громкость, лайки и плейлисты с сохранением в `localStorage`.
- Горячие клавиши: `Space` — пауза, `←/→` — ±5 сек, `↑/↓` — громкость, `/` — поиск.
- Адаптивная мобильная версия с нижней навигацией.
- Логотип и кнопка play — обычные треугольники.

## Запуск

Самый простой способ — **дважды кликнуть `start.bat`** в папке `kokky`. Скрипт поднимет
локальный сервер и откроет `http://localhost:8000` в браузере.

Можно и вручную:

```powershell
cd C:\Users\Admin\kokky
python -m http.server 8000
```

и открыть `http://localhost:8000`.

Открывать `index.html` двойным кликом (`file://`) нельзя: со страницы `file://`
браузер не даёт запрашивать поток и каталог. Приложение показывает подсказку и
кнопку **«Как запустить»**.

## Как устроен звук

- Воспроизведение: **нативный `<audio id="nativeAudio">`**. Транскодинги берутся
  из результатов поиска (`media.transcodings`), поэтому запуск трека — это один
  запрос, а не два. По транскодингу запрашивается прямая ссылка на медиа. Приоритет —
  progressive `audio/mpeg`, затем HLS (`aac_160k` → `aac_96k` → `abr_sq`), который
  проигрывает локальный `vendor/hls.light.min.js`. Если вариант не отдался,
  приложение перебирает остальные, а затем запрашивает трек заново. Ссылки на медиа
  живут около часа, поэтому они кэшируются в `localStorage` (`kokky:stream:sc:*`)
  до истечения, а следующий трек прогревается заранее — переключение и автопереход
  не ждут сеть.
- Резервный путь: встроенный плеер (`https://w.soundcloud.com/player/api.js`)
  в `#scPlayer`. Он создаётся лениво, только если прямой поток не удалось получить
  или воспроизведение дважды подряд сорвалось. Треки с DRM-шифрованием идут сразу
  сюда: их поток браузерный `<audio>` открыть не может, а официальный плеер — может.
  После ошибки резерва приложение возвращается к прямому потоку на следующем треке,
  поэтому один сбой не отключает нативное воспроизведение до конца сессии.
- Если медиа-CDN закрыт у провайдера, после двух сбоев поток автоматически идёт
  через `soundcloud.mediaProxy`: MP3 — подменой `src`, HLS — своим загрузчиком,
  который переписывает плейлист и все сегменты на прокси. Это работает, пока сам
  прокси доступен из сети.
- Поиск: `https://api-v2.soundcloud.com/search/tracks` с публичным `client_id`.
  Каталог не отдаёт CORS, поэтому запрос идёт через прокси. Приложение перебирает
  список `soundcloud.proxies` из `library.js`: сначала `r.jina.ai`, затем
  `corsfix` (доступен из РФ), и запоминает рабочий в `sessionStorage`
  (`kokky:proxy`). `r.jina.ai` из российских сетей отвечает `451`, так что
  переключение происходит автоматически. Свой прокси задаётся в
  `library.soundcloud.proxy` — он всегда идёт первым; см. `worker/README.md`.
- Лента собирается из жанровых запросов (`feedQueries` в `library.js`), а после
  первых действий — из сохранённого вкуса: до трёх артистов/запросов идут первыми,
  остальное добирается базовыми жанрами. Результат кэшируется в `localStorage`
  (`kokky:feed:sc`), чтобы плеер сразу открывался с треками даже при медленной сети.
- Треки артиста собираются из `search/tracks` по имени и дополнительным написаниям
  (`aliases`), с несколькими страницами `next_href`. Совпадения по названию трека
  и по аккаунту, дубли перезаливов схлопываются, официальные загрузки идут первыми.
  На `429` от прокси приложение ждёт `retryAfter` и повторяет запрос.
- Обложки — `artwork_url` каталога в размере 500×500.

## Ограничения источника

- Тридцатисекундные превью (`policy: SNIP`) в каталог не попадают: приложению
  нужен только полный трек. Записи с DRM-шифрованием остаются в каталоге и
  открываются через резервный официальный плеер.
- Некоторые треки правообладатель закрыл для вашей страны: приложение сообщает
  об ошибке и автоматически переключает на следующий трек.
- Прямые ссылки на медиа выдаются на время и привязаны к `client_id`. Если ссылка
  устарела, приложение запрашивает новую.
- Публичный `client_id` может однажды перестать работать. Тогда его нужно заменить в
  `library.js` (`soundcloud.clientId`) на актуальный из веб-клиента каталога.
- `r.jina.ai` имеет лимит запросов (около одного в секунду) и из РФ отвечает
  `451`; приложение автоматически переходит на `corsfix` (лимит 60 запросов в
  минуту). Для стабильной публичной версии разверните свой воркер-прокси
  (папка `worker/`) и укажите его в `library.soundcloud.proxy`.
- Медиа отдаётся с отдельного CDN. Если в вашей сети недоступен и он, приложение
  после двух сбоев пробует провести поток через `soundcloud.mediaProxy`
  (`corsfix`), а затем — через официальный плеер. Совсем без внешнего прокси
  заблокированный CDN не обойти.
- На мобильных браузерах автозапуск со звуком заблокирован: первый трек запускается
  нажатием **play**, дальше автопереход работает.

## Файлы

- `index.html` — разметка, SVG-иконки и контейнер встроенного плеера
- `styles.css` — дизайн, адаптив, анимации
- `app.js` — плеер, лента, поиск, исполнители, плейлисты, лайки, меню, клавиатура
- `library.js` — источник, `client_id`, прокси, жанровые запросы и список артистов
- `vendor/hls.light.min.js` — локальный hls.js для HLS-потоков (Apache-2.0)
- `start.bat` — запуск локального сервера и открытие плеера в браузере
- `assets/` — локальный аватар профиля
